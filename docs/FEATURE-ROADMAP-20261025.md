# 価格改定から複数メニュー反映への段階設計

2026-10-25。独立コピーで実装・検証。公開状況はPRと配信確認を正本とする。

## 今回の完成範囲

現在のメニューのみを対象に、全品／カテゴリー、固定額／率、端数単位（0.01/1/10/100）、四捨五入／切り上げ／切り捨て、変更前後プレビュー、個別除外を提供。
時価・空欄・範囲・通貨名込みは確認対象。表示形式が小数カンマの場合はその規則で数値を読む。既存Pro内の追加機能で、料金・無料機能は変更しない。
確定前に全stateと変更価格一覧をlocalStorageへ保存し、変更後stateの保存まで成功してから画面を更新する。失敗時は変更しない。
バックアップは直前1回分。改定前JSONのダウンロード、セッションをまたいだ取消、既存Undo/Redoに対応。取消は一致する品目IDの改定後価格だけを戻し、後の説明編集などは保持する。価格が競合する場合は中止する。

## 次段階：品目マスターから複数メニューへ

既存の品目ライブラリは **挿入時コピー**。現在も品目名・価格・写真を新IDにコピーし、登録元と挿入先は連動しない。今回ここに参照を後付けしない。

1. ローカルのマスターに `masterId`、`revision`、品目の既定値を持たせる。既存ライブラリはコピー用として残す。
2. メニュー品目に任意の `masterRef:{id,revision}` と、メニュー内の上書き値を追加する。既存品目を名前一致だけで自動連結しない。利用者が候補を選び、同名別商品を区別する。
3. 対象スロットを明示選択して、旧値・マスター新値・ローカル上書きを3者比較する。メニューで編集された値は競合として保持。文字列価格は同じく要確認。
4. 適用前にマスターと全対象スロットをひとつのJSONで退避。schemaVersionを付け、全変更を検証後に書き込む。localStorageは複数キーの原子更新が無いため、journalと復旧規則を設計・fixture検証してから提供する。
5. 任意の1スロット→複数スロットへ段階展開。見つからない参照、削除マスター、競合、容量不足、中断、再読込、取消を検証する。

依存条件：対象メニューの保存単位と識別子、項目別上書きの意味、マスターの削除方針、容量上限での復旧方式を確定する。クラウド・アカウント・料金改定は前提にしない。契約やセキュリティ上の新判断は別途保留。
